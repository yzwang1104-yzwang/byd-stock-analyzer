# Sell Alert — 低点买入后 50% 高点出仓提醒

**日期:** 2026-07-06
**状态:** 已批准
**类型:** 新功能模块

---

## 一、问题陈述

用户持仓策略是"历史低点附近买入 → 等价格回升卖出获利"。但缺乏系统性的卖出提醒——当价格真正回暖时，往往忘记关注、错过出仓窗口。

## 二、核心需求

对于满足"低点买入"条件的持仓股，当实时价格进入**历史最高价的 45%-70%** 区间时，主动提醒用户考虑卖出。

## 三、触发条件（两个条件必须同时满足）

### 条件 1：低点买入

持仓买入均价 ≤ 该股历史最低价 × 1.15

即：买入价比历史最低高出不超过 15%，确保是"在底部买入"。

### 条件 2：接近高点 50% 区间

历史最高价 × 45% ≤ 当前实时价 ≤ 历史最高价 × 70%

下边界（45%）是为了提前预警，上边界（70%）覆盖更宽的出仓决策区间。

## 四、实现方案

### 4.1 新增文件

**`cli/sell_alert.py`**（~120 行）

对标 `cli/buy_alert.py` 的架构，单一职责：只做卖出提醒。

### 4.2 数据流

```
.position_history/*.json            core/data_fetcher.py
        │                                  │
        ├─ load_position()                 ├─ fetch_realtime_quote(code)
        │  → 均价、股数                     │  → 当前实时价
        │                                  │
        └──────────┬───────────────────────┘
                   │
                   ▼
         cli/sell_alert.py
                   │
         ① 判断低点买入：均价 ≤ 历史最低 × 1.15
         ② 判断目标区间：high_all × 45% ≤ cur ≤ high_all × 70%
         ③ 满足 → 表格输出 + 红色告警
```

### 4.3 数据源

| 数据 | 来源 | 刷新策略 |
|------|------|----------|
| 当前价 | 腾讯 qt.gtimg.cn 实时接口 | 每次扫描新拉 |
| 历史最高/最低 | 腾讯 K 线 API 全量数据 | 每次扫描新拉，不做缓存 |
| 买入均价 | .position_history/ JSON | 本地读取 |

### 4.4 输出格式

```
=== 卖出提醒扫描 === 2026-07-06 10:27

  低点买入持仓 → 接近最高点 45%-70% 出仓区间

#   代码      名称    现价    均价    历史最高   目标区间        距区间  盈亏
──  ────────  ──────  ──────  ──────  ────────    ───────────  ────  ──────
 1  600795   国电电力   4.72    4.71     6.80      3.06~4.76    已触发  +0.2%
 2  002594   比亚迪    88.47   78.50   198.00    89.10~138.60   ↓0.7%  +12.7%
──  ────────  ──────  ──────  ──────  ────────    ───────────  ────  ──────

  触发 1 只 | 扫描 7 只持仓 | 4 只符合低点买入条件
  数据: 腾讯实时行情 + 全量K线 | 刷新时间: 10:27:15

  ⚡ 600795 国电电力：当前 4.72 已进入目标区间 3.06~4.76
     买入均价 4.71（距历史最低 +0.8%） → 可考虑出仓
```

**表格列：** 代码 | 名称 | 现价 | 均价 | 历史最高 | 目标区间 | 距区间 | 盈亏

**排序：** 距区间从小到大（已进入的排最前）

**底部：** 已触发的单独红色告警，列出关键数据。

## 五、调度策略

**方案 A — 和 buy_alert 错开：**

| 时间 | 说明 |
|------|------|
| 09:30 | 开盘后第一次 |
| 11:00 | 上午盘中 |
| 14:00 | 下午盘中 |
| 14:50 | 收盘前最后一次 |

新增 **1 个**持久化 Cron 任务（12 → 13）。

## 六、依赖与影响

### 依赖的现有模块（不修改）

| 模块 | 用途 |
|------|------|
| `core/data_fetcher.py` | `fetch_normalized_data(force_refresh=True)` 全量拉取 |
| `core/position_manager.py` | `load_position(code)` 读持仓均价 |
| `core/quick_analyzer.py` | 不直接依赖（sell_alert 自行从 K 线提取 high_all） |

### 不影响现有功能

- `buy_alert.py` 保持不变
- 现有 Cron 任务不变
- Web 仪表盘不变

## 七、边界情况

| 场景 | 处理 |
|------|------|
| 无持仓 | 输出"无持仓" |
| 无低点买入持仓 | 输出"无符合条件的持仓"，列出不符合原因 |
| 全部在区间外 | 正常表格输出，底部"本次无触发" |
| K 线数据拉取失败 | 跳过该股票，标注数据异常 |
| 实时行情不可用 | 跳过该股票，标注行情不可用 |
| 股票代码不存在于缓存 | `fetch_normalized_data` 直接拉取，不需要缓存预置 |

## 九、成功标准

1. 用户在低点买入后，能在价格回暖到 45%-70% 区间时及时收到表格提醒
2. 表格一目了然，已触发股票红色突出显示
3. Cron 任务稳定运行，交易日 4 次自动扫描
4. 不从缓存读数据，每次都是实时数据
